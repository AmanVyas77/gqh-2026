# Frozen-strategy computational reproduction

This is a post-evaluation replay for submission verification, not a new experiment or a new
out-of-sample selection. Both registered decisions remain **rejected**. The original configuration,
strategy modules, original results, holdout lock and original trial log are preserved.

From `cattle_crush/`, after installing the pinned dependencies and acquiring the documented raw data:

```bash
python reproduce_submission.py
```

The runner copies the project to a temporary directory, starts with empty derived-data caches and
empty result tables, and links the existing raw inputs. It executes the full `run_all.py` and
`run_oos.py` pipelines using the existing holdout lock. It never authorizes a purchase or downloads
missing inputs. No API keys or raw licensed data are included here.

**Verified result: PASS.** Both pipeline commands exited 0 and all 25 table comparisons passed.

## Evidence and comparisons

- `report.json`: command exit codes, per-table comparisons, input SHA-256 hashes, computational source
  hashes, exact dependency versions and timestamps. Read its `status` for the result of the latest run.
- `oos_performance_reproduced.csv`: regenerated holdout metrics including recovered turnover.
- `trial_log.csv`: original 171 rows followed by the replay's logged runs, kept separate from the original.
- `run_all.py.log`, `run_oos.py.log`: pipeline output.

Every original CSV in `results/tables/` and `h2_exposure_concentration.json` is compared with regenerated
output. Numeric tolerance is relative 1e-9, absolute 1e-11. The legacy `h2_dsr.csv` layout is reconstructed
from the regenerated project DSR table; it is a column mapping, not a second DSR calculation. Raw log
row counts increase because reproduction adds repeated runs, so those two counters are excluded from
comparison. Distinct trial counts and DSR values are still compared. Original blank holdout turnover is
the only excluded holdout metric; every previously reported holdout return/risk metric is compared.

The first replay completed both pipelines and matched the other 24 table comparisons, but flagged
`h2_dsr.csv` as not generated by `run_all.py`. The driver now recreates that legacy reporting view,
and a complete rerun checks the finalized command. No strategy code changed to resolve this issue.

`run_oos.py` now retains the existing H2 exposure calculation and computes H1 turnover from executed
trade notionals dated inside each holdout window, divided by fixed $1M capital and elapsed calendar
years (365.25 days). Cost scenarios share positions, hence turnover. It uses the same H1 recorded-
notional convention as the development report; cash-final closes without a notional entry are omitted
by that existing convention, a limitation for secondary Variant B. Primary A has no feeder-cattle legs.

The original blank table is retained in `results/tables/oos_performance.csv` for provenance. The artifact
verifier checks the recovered table separately and confirms the original return metrics agree.

## Limits

This verifies reproduction using the existing local raw-input vintages in the pinned environment.
It does not establish that fresh vendor downloads will have identical revisions, that judges have
licensed access, that every post-evaluation review supplement has been regenerated, or that execution
and research-bias limitations disappear. No new hypothesis, threshold, fill rule, cost or sizing rule
was selected. All original limitations and rejection decisions remain.
